# 新 analyze 設計案(第1段階)

## 画面構成
**日々の入力**(スマホは分析結果のみ対応)
- 分析結果入力 / 一覧(PDFあり)
- 工程入力(精米・発芽・製麹・醸造・仕入・調整)— 仕入は量+金額
- 詰口・出荷入力(詰口/販売/試飲/廃棄/遺失/返品)

**帳簿・集計**
- 在庫一覧(原料・瓶・ラベル、数量と金額)
- 月次棚卸し(最終仕入原価法、目視との乖離を調整、CSV/印刷用)
- 詰口台帳・年度別サマリ(SKU毎)
- 酒税(ロット別、軽減80%・100円未満切捨・納付期限・納付済)
- ロット別1ml原価

**設定**
- マスタ(資材・容量・販売先・仕入先・SKU/ロット作番コード)、パスワード変更

## 原価計算
- 評価: 最終仕入原価法(最後に仕入れた単価 × 期末数量)。税法と違えば税法準拠。
- 白米単価 = 玄米の使用金額 ÷ 白米の出来高(精米入力ごとの実績。精米歩合は固定しない)
- 麹原価 = 使用白米の原価 + 種麹費用
- 乳酸・酵母・種麹 = 詰口1mlあたり使用量 × 詰口量 × 単価
- 瓶: 容量ごと、ラベル: SKUごと。詰口本数で減算
- ロット1ml原価 = ロットの使用原料・瓶・ラベル金額 ÷ ロットの詰口総ml
- 期末: 8月末決算。月次は毎月表示、3月末の酒税期末は無視

## 技術
- PHP + SQLite、Xserver。シングルユーザー。
- 日次バックアップ: `bin/backup.sh`(sqlite3 .backup、世代管理)を cron で実行
- 移行: 旧 sakegura.db から `bin/migrate_from_old.php` で取り込み(並行運用)

## 確定事項(2026-11-04)
1. 最終仕入原価法の単価は「期末までの最新の仕入単価」(期末より後の仕入は除く)
2. 精米歩合は固定の90%ではなく、精米入力ごとの実績値を使う(白米単価 = 玄米単価 × 玄米使用量 ÷ 白米出来高)
3. 酒税の税率(円/kL)と軽減率は現行の設定値をそのまま引き継ぐ(移行時に旧 app_settings からコピー。現行値: 税率 100,000円/kL、軽減 80%)
